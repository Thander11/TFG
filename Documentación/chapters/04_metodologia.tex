\chapter{Metodología y herramientas}
\section{Definición de la metodología aplicada}

Desde el principio se definieron cinco fases principales:

\begin{itemize}
    \item Reuniones iniciales.
    \item Búsqueda de información.
    \item Formación y entrenamiento de la nariz electrónica (e\nobreakdash-nose).
    \item Pruebas comparativas con los agentes caninos.
    \item Redacción final de la documentación.
\end{itemize}

Sin embargo, el contenido específico, la secuencia detallada y la carga de trabajo dentro de cada fase no podían fijarse de antemano, ya que dependen de la disponibilidad de recursos, de las personas implicadas y de la información que se vaya obteniendo durante el avance del proyecto. Por este motivo se adoptó un enfoque ligero, apoyado en metodologías ágiles (Scrum y Kanban), que facilita mantener un ritmo constante y una alta capacidad de adaptación ante cambios y necesidades emergentes.

\subsubsection{Control de versiones con Git}
Para garantizar la trazabilidad y poder revertir cambios si fuera necesario, se utiliza Git como sistema de control de versiones. Esto permite mantener un historial detallado de todas las modificaciones realizadas en el código y la documentación, facilitando la colaboración y la gestión del proyecto.
\par

Esto se logra a traves de un repositorio privado en GitHub gestionado mediante ramas, en el que se almacena todo el código fuente, documentación, información recopilada a modo de apuntes y recursos relacionados con el proyecto.

\subsubsection{Sprints adaptativos}
Se define como sprint a cada una de las fases anteriormente mencionadas. La duración de cada sprint se fija en funcion de una estimación del tiempo que se cree necesario para lograr los objetivos establecidos para esa fase.
\par

Antes de que inicie cada sprint (En los ultimos días del sprint anterior), se hace una organiacación aproximada de las tareas a realizar. Al comenzar el sprint, se hace una planificación más detallada de las tareas a realizar, asignando prioridades y fijando fechas de las posibles reuniones con los implicados. Durante el sprint, se revisa periódicamente el progreso y se ajustan las tareas y prioridades según sea necesario.

\subsubsection{Github Projects y Tablero Kanban}

Para la gestión de tareas, sprints y el seguimiento del progreso del proyecto, se utiliza GitHub Projects (En el repositorio anteriormente mencionado), que cuenta con un tablero Kanban integrado, como el que se muestra en la Figura~\ref{fig:tablero_kanban}. Este tablero permite visualizar las tareas en diferentes estados (Backlog, Ready, In progress, Done) y facilita la organización y priorización de las actividades. Cada tarea se representa como una tarjeta que puede moverse entre las columnas según su estado actual, proporcionando una visión clara del avance del proyecto.

Esta nariz electrónica ha sido diseñada y construida en el laboratorio de sensores de la Escuela de Ingenierías Industriales de Badajoz por Cristina Brugera Salas, bajo la supervisión del Dr.\ Jesús Lozano Rogado, cotutor de este trabajo.

En esta placa es donde se encuentran los sensores de gases y el microcontrolador PIC32MM0256GPM048, además de contar con un módulo Bluetooth Rn4871 para la comunicación con una aplicación movil que la controla, y una entrada microUSB para poder conectarla a la corriente y cargar la bateria con la que cuenta. El conjunto de sensores que componen esta nariz electrónica es el siguiente:
\begin{itemize}
    \item \textbf{SCD40} (PA): Sensor de CO$_2$, temperatura y humedad, fabricado por Sensirion.
    \item \textbf{SGP40} (MOS): Sensor de COV, fabricado por Sensirion.
    \item \textbf{BME688} (MOS): Sensor de presión, temperatura, humedad, COV, VSC y gas, fabricado por Bosch.
    \item \textbf{ENS160} (MOS): Sensor de COV, calidad del aire, VOX y NO$_2$, fabricado por ScioSense.

\subsubsection{Limpieza del dataset}
Para la limpieza y preprocesamiento de los datos obtenidos durante la fase de toma de muestras, se busca crear un script que automatice este proceso y facilite la preparación del dataset para su posterior análisis y entrenamiento de la ANN\@. Existen varias posibilidades para llevar a cabo esta tarea, entre las que se incluyen:

\begin{itemize}
    \item \textbf{Python:}
    \begin{itemize}
        \item Cuenta con librerias como NumPy, Pandas, Matplotlib o Polaras para el procesamiento y visualización de datos.
        \item Sencillo de aprender y utilizar.
        \item Amplia comunidad y soporte.
        \item Limpieza reproducible.
        \item Familiaridad con el lenguaje.
    \end{itemize}
    \item \textbf{R:}
    \begin{itemize}
        \item Limpieza reproducible.
        \item Muy usado en investigación.
    \end{itemize}
    \item \textbf{Bash + herramientas UNIX:}
    \begin{itemize}
        \item Potente para archivos de texto.
        \item Muy rápido.
        \item Limpieza reproducible.
        \item Cero dependencias.
    \end{itemize}
    \item \textbf{SQL + scripts:}
    \begin{itemize}
        \item Exportación muy limpia.
        \item Limpieza reproducible.
    \end{itemize}
    \item \textbf{Apache Spark:}
    \begin{itemize}
        \item Escalable.
        \item Limpieza reproducible.
        \item Muy usado en entornos de investigación grandes.
    \end{itemize}
\end{itemize}

Dado que se trata de un script sencillo, que no tienen que procesar una gran cantidad de datos, se ha optado por utilizar Python para la limpieza de dichos datos. Esta elección se basa en la familiaridad con el lenguaje, la disponibilidad de librerías especializadas y la facilidad para crear scripts reproducibles que faciliten el análisis posterior.

\subsubsection{Entrenamiento de la ANN}
Existen diversas herramientas y frameworks para el desarrollo y entrenamiento de redes neuronales artificiales (ANN\@). Algunas de esas opciones son:

\begin{itemize}
    \item \textbf{Lenguajes:}
    \begin{itemize}
        \item \textbf{Python:}
        \begin{itemize}
            \item Buen ecosistema y librerías.
            \item Sencillo de aprender y utilizar.
            \item Amplia comunidad y soporte.
            \item Flexibilidad y prototipado.
            \item Familiaridad con el lenguaje.
        \end{itemize}
        \item \textbf{C++:}
        \begin{itemize}
            \item Velocidad inigualable de ejecución.
            \item Gestión manual de memoria.
        \end{itemize}
        \item \textbf{Julia:}
        \begin{itemize}
            \item Gran velocidad de ejecución.
            \item Resuelve el ``problema de los dos lenguajes'' (puedes investigar y producir en el mismo lenguaje sin perder velocidad).
        \end{itemize}
        \item \textbf{Mojo:}
        \begin{itemize}
            \item Combina la sintaxis de Python con el rendimiento de C++.
            \item Está diseñado específicamente para hardware de IA (TPUs y GPUs).
        \end{itemize}
    \end{itemize}

    \item \textbf{Entornos de ejecución:}
    \begin{itemize}
        \item \textbf{Orange/KNIME:}
        \begin{itemize}
            \item Permiten crear tuberías de datos completas (limpiar, entrenar y evaluar) de forma visual.
        \end{itemize}
        \item \textbf{Kaggle Kernels:}
        \begin{itemize}
            \item Entorno en la nube listo para ejecutar notebooks.
            \item Acceso a GPUs y TPUs.
            \item Comunidad activa y competiciones.
            \item Enfocado en ciencia de datos.
            \item Set de datos ya listos para usar.
        \end{itemize}
        \item \textbf{Google Colab:}
        \begin{itemize}
            \item Entorno en la nube listo para ejecutar notebooks.
            \item Acceso a GPUs y TPUs de Google.
            \item Integración con Google Drive.
            \item Fácil de compartir y colaborar.
        \end{itemize}
    \end{itemize}

    \item \textbf{Frameworks:}
    \begin{itemize}
        \item \textbf{PyTorch:}
        \begin{itemize}
            \item Usa ``gráficos dinámicos'', lo que permite cambiar el modelo en pleno entrenamiento.
            \item Facilidad de depuración; puedes usar las herramientas estándar de Python para encontrar errores.
            \item Ecosistema enorme.
            \item Familiaridad con el framework.
        \end{itemize}
        \item \textbf{TensorFlow / Keras:}
        \begin{itemize}
            \item Producción y despliegue.
            \item Ecosistema móvil.
            \item Su interfaz simplificada permite crear redes neuronales complejas en pocas líneas de código.
        \end{itemize}
        \item \textbf{Scikit-Learn:}
        \begin{itemize}
            \item Simplicidad.
            \item Herramientas estadísticas integradas.
            \item No requiere GPU, corre en cualquier ordenador con muy pocos recursos.
        \end{itemize}
    \end{itemize}
\end{itemize}

Para este proyecto se ha decidio usar Python (concretamente la versión 3.12) como lenguaje de programación debido a sus ventajas, especialmente por ser el mas usado para el entrenamiento de modelos de inteligencia artificial y el gran soporte de la comunidad. En cuanto al entorno de ejecución, se ha optado por Google Colab, ya que proporciona acceso gratuito a GPUs y TPUs, facilitando el entrenamiento de modelos complejos sin necesidad de contar con hardware potente localmente y pudiendo guardar los notebooks, modelos y datasets directamente en Google Drive\@. Finalmente se han elegido tanto PyTorch como Keras como frameworks para el desarrollo y entrenamiento de la ANN (Aunque se usarán tambíen librerias de Scikit-Learn, Pandas y NumPy). Se entrenarán modelos con ambos frameworks y los mismos datos para comparar resultados y determinar cuál se adapta mejor a las necesidades del proyecto.

\subsubsection{Aplicación Bluetooth}
Para el desarrollo de la aplicación móvil que se comunicará con la nariz electrónica a través de Bluetooth, se han considerado varias opciones de herramientas:

\begin{itemize}
    \item \textbf{Flutter:}
    \begin{itemize}
        \item Es muy estable y permite escanear, conectar y escuchar notificaciones del módulo Bluetooth de forma sencilla.
        \item Permite cargar el modelo desde la carpeta de activos (assets).
        \item Es reactivo, la interfaz se actualiza sola en cuanto el modelo cambia su predicción de ``Negativo'' a ``Positivo''.
        \item Permite crear una aplicación multiplataforma.
        \item Ofrece una gran velocidad en la transferencia de datos.
    \end{itemize}
    \item \textbf{React Native:}
    \begin{itemize}
        \item Es potente pero la configuración inicial (permisos en Android/iOS) suele ser tediosa.
        \item Es web, permitiendo que la aplicación se use en cualquier plataforma.
        \item Permite la integración con IA\@.
        \item Gran facilidad para crear un selector de modelos y gestionar la lógica de temporizadores (el tiempo límite de detección) usando hooks de React.
    \end{itemize}
    \item \textbf{Kotlin:}
    \begin{itemize}
        \item Usa APIs oficiales (BluetoothGatt en Android).
        \item Tienes el control total sobre la latencia.
        \item Permite la integración con IA usnado librerías nativas de TensorFlow Lite para Android y CoreML para iOS\@.
        \item Permite un consumo de batería más eficiente si la app debe estar encendida durante horas procesando datos.
    \end{itemize}
    \item \textbf{Capacitor:}
    \begin{itemize}
        \item Acceso directo a las APIs nativas de iOS y Android mediante Plugins.
        \item Permite gestionar el ciclo de vida completo: escanear el módulo Bluetooth, conectarse, descubrir servicios y suscribirse a notificaciones.
        \item Puedes ejecutar tu modelo directamente en la capa web usando TensorFlow.js.
        \item Permite crear aplicaciones multiplataforma.
        \item Es un puente entre tecnologías web y móviles nativas.
        \item Existe un plugin para usar el SDK de Google, lo que permite que el modelo corra de forma nativa (más rápido) mientras se controla desde JavaScript.
    \end{itemize}
\end{itemize}

En este caso se toma como prioridad la velocidad de la transferencia de datos, asurando que la aplicación pueda procesar la información recibida de la nariz electrónica en tiempo real.
\par

Flutter se posiciona como la opción ganadora para este proyecto porque ofrece un equilibrio perfecto entre el alto rendimiento de las aplicaciones nativas y la agilidad de desarrollo multiplataforma, algo crítico cuando se trabaja con hardware y modelos de inteligencia artificial en tiempo real. No es tan difícil como programar en Nativo (Kotlin/Swift), pero es mucho más potente para hardware que Capacitor. A diferencia de Capacitor, que depende de una capa web y un puente de comunicación que puede generar latencia, Flutter maneja la entrada de datos del módulo Bluetooth de forma directa y eficiente mediante Streams de forma nativa en su lenguaje (Dart), permitiendo procesar el flujo constante de sensores sin interrupciones. Además, su capacidad para ejecutar la red neuronal en Isolates (hilos de ejecución independientes) garantiza que el análisis intensivo de los datos no congele la interfaz de usuario, manteniendo la aplicación fluida mientras la IA ``busca'' la sustancia objetivo. Esto, sumado a la robustez de librerías como ``flutter\_blue\_plus'' para la gestión estable del Bluetooth y la facilidad para cargar y descargar dinámicamente diferentes modelos de TensorFlow Lite aprovechando la aceleración por hardware del móvil, lo convierte en la herramienta más fiable para convertir un smartphone en el procesador inteligente de una nariz electrónica.
